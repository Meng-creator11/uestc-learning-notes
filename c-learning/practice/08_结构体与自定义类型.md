# 08 · 结构体与自定义类型

> **前置知识**：01–07 章
> **题量**：24 题（A 组 10 / B 组 8 / C 组 6）
> **目标**：学会"把相关的数据打包在一起"，这是从"写练习题"到"写程序"的关键一步。
> **学完这章你能做到**：一个学生不再是一堆散落的数组，而是"一个对象"。

---

## 开始前：知识点自查

- [ ] `struct` 定义的是**类型**，不是变量；`struct Student s;` 才创建变量
- [ ] 成员访问：变量用 `.`，指针用 `->`
- [ ] 结构体可以**整体赋值**（`s1 = s2`），但**不能用 `==` 比较**
- [ ] 结构体作函数参数默认是**值传递**（整个结构体被复制一份），大结构体要用指针
- [ ] `sizeof(struct)` 往往**大于**各成员之和（内存对齐）
- [ ] `typedef struct {...} T;` 之后可以直接写 `T s;`
- [ ] `union` 的所有成员**共用同一块内存**，大小等于最大成员
- [ ] `enum` 本质是整数常量，可读性更好

## A 组 · 定义与使用（1–10）

### 1. 第一个结构体 ★

**要求**：定义学生结构体（学号、姓名、三科成绩），创建一个变量，赋值后输出。

**样例输出**
```
学号: 101
姓名: 张三
成绩: 80 90 85
总分: 255
```

**要求**：
1. 定义写在 `main` 外面（或里面都行，但外面更常用）
2. 成员用 `.` 访问

**必须回答**：`struct Student` 和 `int` 有什么区别？（前者是你自己造的类型，后者是内置的。**定义结构体 = 造一个新类型**。）

---

### 2. 结构体数组 ★

**要求**：读入 `n` 个学生信息，存入结构体数组，输出。

**样例输入/输出**
```
2
101 张三 80 90 85
102 李四 70 60 75
->
101 张三 80 90 85 总分 255
102 李四 70 60 75 总分 205
```

**提示**：`struct Student s[100];`，访问 `s[i].name`、`s[i].score[0]`。

**和第 05 章对比**：那时候你用 `int a[100][4]` 存，现在用结构体。**哪个读起来更清楚？** 这就是结构体的价值。

---

### 3. 结构体指针与 `->` ★★

**要求**：用指针访问结构体成员，三种写法都试一遍，确认等价：

```c
struct Student s = {101, "张三", {80, 90, 85}, 255};
struct Student *p = &s;

p->id            /* ① */
(*p).id          /* ② */
s.id             /* ③ */
```

**必须回答**：
1. 为什么需要 `->`？（因为 `*p.id` 会被解析成 `*(p.id)`，`p` 不是结构体，没有 `.id`）
2. `(*p).id` 里的括号为什么不能省？
3. 结构体指针 `p++` 会跳多少字节？（`sizeof(struct Student)`）

---

### 4. 结构体作函数参数 ★★★

**要求**：写两个函数，一个值传递，一个指针传递：

```c
void print_student(struct Student s);         /* 值传递 */
void raise_score(struct Student *s, int add); /* 指针传递 */
```

调用 `raise_score(&s, 5)` 后观察分数是否变化。

**必须回答**：
1. 值传递时，函数里改分数，`main` 里的会变吗？为什么？
2. 一个 `struct Student` 有 100 多字节，每次值传递都要复制一遍——代价是什么？
3. 什么时候用值传递（不修改），什么时候用指针（要修改 / 结构体很大）？

**结论**：**大结构体一律传指针**；如果只是读，加 `const`：`void print(const struct Student *s)`。

### 5. 嵌套结构体 ★★

**要求**：定义日期结构体，再定义一个"生日"字段嵌在学生里，输出格式化的生日。

```c
struct Date { int year, month, day; };
struct Student {
    int id;
    char name[32];
    struct Date birthday;
};
```

**样例输入/输出**
```
101 张三 2008 5 12
-> 张三的生日是 2008-05-12
```

**必须回答**：访问嵌套成员怎么写？（`s.birthday.year`，两层点。）如果 `s` 是指针呢？（`s->birthday.year`。）

---

### 6. `typedef` 简化 ★★

**要求**：用 `typedef` 把结构体重命名，让代码更短：

```c
typedef struct Student {
    int id;
    char name[32];
    int score[3];
} Student;      /* 尾部的 Student 是别名 */

/* 现在可以写 */
Student s;
Student *p;
```

**必须回答**：
1. `typedef` 到底做了什么？（给类型起了个新名字，**不创建新类型**）
2. 为什么很多人写成 `typedef struct {...} Student;`（省略结构体标签）？有什么缺点？（无法自引用，链表就不能这么写）

**注意**：链表节点**必须**有标签：`typedef struct Node { struct Node *next; } Node;`

---

### 7. 结构体的赋值与比较 ★★

**要求**：验证下面两件事：

```c
Student a = {101, "张三", {80,90,85}};
Student b;
b = a;                   /* ① 合法吗？ */
if (a == b) ...          /* ② 合法吗？ */
```

**必须回答**：
1. `b = a` 是**逐字节复制**还是复制指针？（逐成员复制，包括数组成员也会被完整复制）
2. `a == b` 为什么不能编译？（C 没有为结构体生成 `==` 运算符）
3. 想比较两个学生是否相同，怎么写？（逐成员比较：`a.id == b.id && strcmp(a.name, b.name) == 0 && ...`）

**必须注意**：如果结构体里有**指针成员**，`b = a` 只是复制指针值（**浅拷贝**），两个结构体指向同一块内存——这是第 09 章的重点。

### 8. `sizeof` 与内存对齐 ★★★

**要求**：输出下面每个结构体的大小，并**解释**为什么。

```c
struct A { char c; int i; };
struct B { char c; double d; };
struct C { char a; char b; int c; };
struct D { char a; int b; char c; };
struct E { char a; char b; char c; };
```

**样例输出**
```
A = 8
B = 16
C = 8
D = 12
E = 3
```

**必须回答**：
1. `A` 是 1 + 4 = 5，为什么是 8？（`int` 要 4 字节对齐，`c` 后面补 3 个字节）
2. `D` 是 1 + 4 + 1 = 6，为什么是 12？（尾部还要补齐到 4 的倍数，因为结构体整体对齐）
3. **怎么调整成员顺序让 `D` 变小？**（`char a; char c; int b;` → 8 字节）
4. 为什么需要对齐？（CPU 读未对齐的内存要多次访问，甚至某些架构直接崩）

**这是笔试必考题**。掌握两条规则就够了：
- 每个成员的偏移量必须是**自身大小**的整数倍
- 结构体总大小必须是**最大成员大小**的整数倍

### 9. 枚举类型 ★★

**要求**：定义枚举 `enum Weekday { MON, TUE, WED, THU, FRI, SAT, SUN };`，读入 0–6，输出对应的星期名（中文）。

**样例输入/输出**
```
0 -> 星期一
6 -> 星期日
7 -> 输入错误
```

**要求**：
1. 用 `switch` 分发，`case` 里用枚举名（`case MON:`）而不是数字
2. 输出枚举的实际整数值，验证 `MON == 0`

**必须回答**：
1. 枚举值默认从几开始？可以指定吗？（`enum { A = 5, B, C };` → 5, 6, 7）
2. `enum` 和 `#define` 比，好在哪？（有类型、有作用域、调试器能显示名字）
3. `enum` 变量能赋任意整数吗？（C 里可以，但不推荐；C++ 严格禁止）

### 10. 联合体 `union` ★★★

**要求**：定义并测试：

```c
union U {
    int i;
    char c[4];
    double d;
};
```

1. 输出 `sizeof(union U)`
2. 给 `i` 赋值 `0x41424344`，然后打印 `c[0]` ~ `c[3]`
3. 说明这个现象意味着什么

**样例输出**
```
sizeof = 8
i = 0x41424344
c[0]=0x44, c[1]=0x43, c[2]=0x42, c[3]=0x41
（小端序：低字节在前）
```

**必须回答**：
1. `sizeof` 为什么是 8 而不是 4+4+8？（所有成员**共用**一块内存，大小取最大的）
2. 给 `i` 赋值后，`c` 为什么变了？（它们是同一块内存的不同解读方式）
3. `union` 的实际用途是什么？（节省内存 / 类型双关 / 判断大小端）
4. **判断本机是大端还是小端**，写个小程序验证

**这题讲的是"同一块内存，不同的看法"**，理解了这个，指针的很多行为就不神秘了。

### 11. 按总分排序 ★★★

**要求**：读入 `n` 个学生，按总分**降序**排序后输出。

**样例输入/输出**
```
3
101 张三 80 90 85
102 李四 70 60 75
103 王五 100 95 98
->
103 王五 293
101 张三 255
102 李四 205
```

**要求**：写两个版本：
1. 冒泡排序（整条记录交换，用临时 `Student` 变量）
2. `qsort` + 比较函数

**必须回答**：
1. 冒泡交换时，为什么要用 `Student tmp = s[i];` 而不是只交换总分？
2. `qsort` 的比较函数怎么写？
```c
int cmp_total_desc(const void *a, const void *b)
{
    const Student *x = a, *y = b;
    /* 降序：y->total - x->total 或 (x->total < y->total) - ... */
}
```
3. 为什么 `qsort` 的比较函数**不能直接返回 `x->total - y->total`**？（可能溢出，虽然总分不会，但要好习惯）

### 12. 多关键字排序 ★★★

**要求**：排序规则（依次比较）：
1. 总分降序
2. 总分相同 → 数学降序
3. 还相同 → 学号升序

**样例输入/输出**
```
3
101 张三 80 90 85    (255)
102 李四 90 80 85    (255)
103 王五 100 95 98   (293)
-> 103, 101, 102
```

**提示**：比较函数写成"逐级判断"的形式：
```c
if (x->total != y->total) return y->total - x->total;
if (x->math  != y->math)  return y->math  - x->math;
return x->id - y->id;
```

**必须回答**：这个写法为什么是**稳定**的？如果两个学生三个键都相同怎么办？（那就随便排，说明它们"等价"。）

**这是实际开发中排序的真实样子**：几乎不会只按一个字段排。

### 21. 复数运算 ★★★

**要求**：定义复数结构体，实现加、减、乘、除，以及求模。

```c
typedef struct { double re, im; } Complex;
```

**样例输入/输出**
```
(1+2i) + (3+4i) = 4.00+6.00i
(1+2i) * (3+4i) = -5.00+10.00i
|3+4i| = 5.00
```

**提示**：乘法 `(a+bi)(c+di) = (ac-bd) + (ad+bc)i`；除法要乘共轭，分母是 `c²+d²`。

**必须处理**：除数为 0（`c²+d² == 0`）。

**必须回答**：为什么复数适合用结构体表示？（两个分量必须绑定在一起，且都参与运算。）

### 22. 分数运算 ★★★

**要求**：定义分数结构体（分子、分母），实现加、减、乘、除，**结果要约分**，分母为 1 时只输出整数。

```c
typedef struct { int num, den; } Fraction;
```

**样例输入/输出**
```
1/2 + 1/3 = 5/6
1/2 + 1/2 = 1
2/3 * 3/4 = 1/2
```

**提示**：
1. 加法：`a/b + c/d = (ad + bc) / (bd)`，然后约分
2. 约分用 `gcd(|num|, |den|)`
3. 分母必须保持正数（`1/-2` 要变成 `-1/2`）

**必须注意**：中间结果可能溢出（`ad + bc`），用 `long long` 算。

### 23. 日期计算 ★★★

**要求**：定义日期结构体，实现：

1. 判断两个日期相差多少天
2. 判断某天是星期几
3. 日期加 `n` 天后的日期

**样例输入/输出**
```
2024 1 1 到 2024 12 31 相差 365 天
2026 10 19 是 星期一
2024 2 28 加 2 天 = 2024-03-01
```

**提示**：
- 相差天数：都转成"从公元 1 年 1 月 1 日算起的天数"再相减
- 星期几：`(总天数 + 偏移) % 7`
- 加天数：逐天加，跨月/跨年要处理（用第 02 章的 `days_in_month`）

**必须做到**：把"日期 → 天数"和"天数 → 日期"拆成两个函数，**复用**。

**这题把第 02、04、08 章的知识全串起来了**，是很好的阶段检验。

### 24. 图书管理系统 ★★★

**要求**：完整实现一个图书管理程序：

```c
typedef struct {
    char isbn[20];
    char title[64];
    char author[32];
    double price;
    int    stock;      /* 库存 */
    int    borrowed;   /* 借出数量 */
} Book;
```

**功能**：
```
1. 入库（新增图书，ISBN 不能重复）
2. 查询（按 ISBN / 书名 / 作者）
3. 借书（库存 -1，借出 +1；库存为 0 时拒绝）
4. 还书（库存 +1，借出 -1；借出为 0 时拒绝）
5. 列表（按书名排序，显示库存状态）
6. 统计（总种类、总册数、总价值、缺货的书）
0. 退出
```

**验收标准**：
1. 所有操作都有输入校验（空输入、非法数字、ISBN 重复）
2. 库存和借出数量的**不变式**始终成立：`stock + borrowed == 总册数`
3. 排序、查找、统计各自独立成函数
4. `main` 只负责菜单分发
5. 退出时干净（数组版不用 `free`，但要确保没有越界）

## 易错点速查

| # | 错误 | 后果 | 正确 |
|---|---|---|---|
| 1 | `struct Student s; s = {...};` | 编译错误 | 声明时初始化 `= {...}` |
| 2 | `*p.id` | 优先级错，编译错误 | `(*p).id` 或 `p->id` |
| 3 | `if (a == b)` 比较结构体 | 编译错误 | 逐成员比较 |
| 4 | 值传递大结构体 | 复制开销大 | 传指针 + `const` |
| 5 | 以为 `sizeof` 等于成员和 | 算错 | 考虑对齐 |
| 6 | `typedef struct {...} T;` 写链表 | 无法自引用 | 保留标签 `struct Node` |
| 7 | 结构体里有 `char *name` 后直接 `=` | 浅拷贝，两个指向同一块 | 深拷贝（`strdup`/`malloc`+`strcpy`） |
| 8 | 排序只交换一个字段 | 数据错位 | 整条记录交换 |
| 9 | 删除后没更新 `n` | 越界/多输出 | 返回新长度 |
| 10 | `union` 当成结构体用 | 数据互相覆盖 | 一次只用一个成员 |

## 参考答案（仅分析题）

**第 8 题详见**
```
A: char(1) + pad(3) + int(4)          = 8
B: char(1) + pad(7) + double(8)       = 16
C: char(1) + char(1) + pad(2) + int(4) = 8
D: char(1) + pad(3) + int(4) + char(1) + pad(3) = 12
E: char(1) * 3                        = 3
```
`D` 调整成 `char a; char c; int b;` 后：1 + 1 + pad(2) + 4 = **8**。

**第 10 题**：`sizeof(union U) = 8`（最大成员 `double`）。给 `i` 赋值 `0x41424344` 后，`c[0]` 是 `0x44`，说明**低字节存在低地址** → 小端序。判断方法：`int x = 1; if (*(char*)&x == 1) 小端;`
