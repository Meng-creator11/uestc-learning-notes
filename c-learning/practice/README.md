## 这份题库怎么用

**三条规矩**（比题目本身更重要）：

1. **先写，再看。** 每题先自己想 10 分钟，写不出来就先按提示搭骨架，还是不会就先跳过，第二天再看。卡住的题第二天往往一遍就过。
2. **不抄答案。** 这套题**故意不提供编程题的参考代码**。编程是手上功夫，看会了和敲出来是两回事。
3. **必须自己验证。** 每题都给了样例输入/输出，跑出来对不上就是错——不要去猜"大概对了"。

**推荐的三遍刷法：**

| 遍数 | 做什么 | 通过的标志 |
|---|---|---|
| 第一遍 | 只看 ★ 基础题，做出 80% | 语法不再报错，能独立调试 |
| 第二遍 | 回头补 ★★ 进阶题，加做错过的题 | 能自己想到"该用什么套路" |
| 第三遍 | 只做 ★★★ 和综合实战 | 能拆解需求、自己设计数据结构 |

**每道题怎么标注：**

- ★ 基础：单一知识点，20 行以内
- ★★ 进阶：需要组合两个以上知识点，50 行左右
- ★★★ 挑战：需要算法思路或数据结构设计，100 行以上

## 编译与运行

和你的现有练习保持一致（**源码存 UTF-8，exe 中的中文用 GBK**）：

```bash
cd practice
gcc -Wall -fexec-charset=GBK 01.c -o 01.exe
./01.exe
```

三件必须做的事：

1. **`-Wall` 一定加上。** 漏写 `&`、格式符不匹配、变量没初始化，它都会喊你。
2. **一次只写一个 `.c` 文件，一个 `main`。** 想试多个版本就复制成 `01_2.c`。
3. **遇到 Segmentation fault，先看下标和 `&`。** 90% 的崩溃出于这两个地方。

> 数组越界 `-Wall` 抓不到，编译通过 ≠ 运行正确。每写完一个循环，自己念一遍：
> 「`i` 从几开始？到几结束？有没有碰到 `n`？」

## 一个自查习惯

每写完一题，问自己三个问题：

1. **边界对不对？** 输入 0 个、1 个、最大值时会不会崩？
2. **有没有写死？** 把样例里的 5 改成 7，代码还跑得对吗？
3. **能不能讲出来？** 合上代码，能不能向别人说清每一步在干什么？

第三条过不了，说明是"碰对的"，不是"写对的"。这题要重做。
