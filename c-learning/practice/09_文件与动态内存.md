# 09 · 文件与动态内存

> **前置知识**：01–08 章
> **题量**：22 题（A 组 8 / B 组 6 / C 组 8）
> **目标**：让程序的数据"活过这一次运行"，并学会在运行时按需申请内存。
> **学完这章**：你的程序终于能"记住东西"了。

---

## 开始前：知识点自查

- [ ] `FILE *fp = fopen(路径, 模式);` 用完必须 `fclose(fp)`
- [ ] 模式：`"r"` 读、`"w"` 写（**清空**）、`"a"` 追加、`"rb"/"wb"` 二进制
- [ ] **`fopen` 可能返回 `NULL`**，必须检查（文件不存在、没权限）
- [ ] 文本模式和二进制模式在 Windows 上的区别（`\r\n` 的处理）
- [ ] `feof` 是"**读失败之后**才置位"，所以 `while (!feof(fp))` 会多循环一次
- [ ] `malloc` 必须配 `free`，`free` 后置 `NULL`
- [ ] `realloc` 可能搬家，要用返回值覆盖原指针

### 1. 写文件与读文件 ★

### 3. 逐行读写 ★★

**要求**：读入一个文本文件，给每一行加上行号后输出到另一个文件。

**样例输入（in.txt）**
```

```

**样例输出（out.txt）**
```

```

**提示**：
```c

    /* 注意 buf 末尾可能有 '\n' */
    fprintf(out, "%d: %s", ++line, buf);

```

**必须回答**：
1. `fgets` 返回 `NULL` 表示什么？（读到文件末尾，或出错）
2. 为什么用 `fgets` 而不用 `fscanf("%s")`？（`fscanf` 遇空格就停，一行有空格就被拆成多个"词"）

## B 组 · 定位、参数与健壮性（9–14）

### 9. 求文件大小 ★★

**要求**：用 `fseek` + `ftell` 求一个文件的字节数。

**样例输出**
```
文件大小: 1024 字节
```

**提示**：
```c
fseek(fp, 0, SEEK_END);
long size = ftell(fp);
rewind(fp);          /* 别忘了回到开头 */
```

**必须回答**：
1. `fseek(fp, 0, SEEK_END)` 做了什么？（把读位置移到末尾）
2. `ftell` 返回什么？（当前位置相对文件开头的字节偏移）
3. 为什么要求大小之后必须 `rewind`？（否则后续读取从末尾开始，什么都读不到）

**注意**：`ftell` 返回 `long`，超大文件（> 2GB）会溢出，要用 `fseeko` / `ftello`（POSIX）或平台 API。

**提示**：
```c
fseek(fp, k * sizeof(Record), SEEK_SET);
fread(&rec, sizeof(Record), 1, fp);
```

**必须回答**：
1. 为什么二进制文件能"直接跳到第 k 条"？（每条记录**定长**，偏移可以算出来）
2. 文本文件能这样跳吗？为什么？（每行长度不定，只能一行行数）
3. 这就是"数组"和"文件"的对应关系：**文件 = 磁盘上的数组**。想通这一点没有？

**进阶**：实现"修改第 k 条记录"（读出来、改、再 `fseek` 回去写）。

### 12. `feof` 的坑 ★★★

**要求**：先跑下面两个版本，观察差异，然后解释。

```c
/* 版本 A：常见错误写法 */
while (!feof(fp)) {
    fgets(buf, sizeof(buf), fp);
    printf("%s", buf);        /* 最后一行会被打印两次 */
}

/* 版本 B：正确写法 */
while (fgets(buf, sizeof(buf), fp) != NULL) {
    printf("%s", buf);
}
```

**必须回答**：
1. `feof` 什么时候才返回"真"？（**在一次读操作失败之后**，不是之前）
2. 版本 A 为什么最后一行会重复？（读到末尾时 `fgets` 失败，`buf` 保持上一次的内容，但循环还没退，又打印了一遍）
3. 那 `feof` 到底该什么时候用？（读完**之后**判断"是正常结束还是出错"）

**记住一句话**：**用返回值判断循环，不要用 `feof` 判断循环。**

**提示**：`rename(old, new)` 和 `remove(path)` 都返回 0 表示成功。

**必须回答**：

2. 为什么删除前要**二次确认**？（这是不可逆操作——写工具时永远要问一句）

### 16. 动态数组 ★★

**要求**：运行时读入 `n`，分配 `n` 个 `int`，读入数据、排序、输出、释放。

**样例输入/输出**
```
5
5 1 4 2 8
-> 1 2 4 5 8
```

**要求**：`n` 最大 1000000，**不许开固定大小的数组**。

**必须回答**：
1. 为什么不能 `int a[1000000];`？（栈空间通常只有 1–8MB，100 万个 int 要 4MB，可能爆栈）
2. 堆和栈的区别？（栈自动回收、空间小；堆手动管理、空间大）
3. 忘了 `free` 会怎样？（进程退出时操作系统会回收，但长时间运行的程序会越吃越多）

### 17. 动态二维数组 ★★★

**要求**：运行时确定行数 `m`、列数 `n`，创建一个 `m×n` 的二维数组。

**要求**：写两种方案：

**方案一：指针数组**
```c
int **a = malloc(m * sizeof(int *));
for (i = 0; i < m; i++)
    a[i] = malloc(n * sizeof(int));
/* 释放时要反过来，先释放每一行，再释放 a */
```

**方案二：一维模拟二维**
```c
int *a = malloc(m * n * sizeof(int));
/* 访问 a[i*n + j] */
```

**必须回答**：
1. 方案一释放的顺序为什么不能反？（先 `free(a)` 就丢了行指针，那些行再也释放不了）
2. 方案二的内存是**连续**的，这有什么好处？（缓存友好、可以当一维数组传参、只 `free` 一次）
3. C99 的变长数组 `int a[m][n];` 可以吗？（可以，但在栈上，`m*n` 大了会爆栈）

**推荐方案二**，实际项目中更常用。

### 18. `realloc` 扩容 ★★★

**要求**：实现一个"边读边扩容"的动态数组：初始容量 4，满了就翻倍。

**样例输出**
```
读入: 1 2 3 4 5 6 7
容量变化: 4 -> 8
最终: 7 个元素，容量 8
```

**要求**：
1. `realloc` 的返回值**必须**用临时变量接，检查后再赋值
2. 记录 `size`（已用）和 `capacity`（容量）两个变量

**必须回答**：
1. 为什么不能直接 `a = realloc(a, new_size);`？（如果失败返回 `NULL`，原来的 `a` 就丢了 → 泄漏）
2. `realloc` 一定会搬家吗？（不一定，后面空间够就原地扩展）
3. 翻倍扩容的策略为什么好？（每次插入的平均代价是 `O(1)`，这叫"均摊分析"）

**这个"size + capacity + 翻倍"的模式，是 `std::vector`、`ArrayList`、`Python list` 的共同实现**。你手写一遍，就懂了所有动态数组。

**这题的目的是建立"敬畏感"**：内存不是免费的。

### 20. 内存错误五连 ★★★

**要求**：下面五段代码都有问题，逐个指出**错误类型**和**后果**。

```c
/* A：free 两次 */
int *p = malloc(sizeof(int));
free(p);
free(p);

/* B：free 栈上的地址 */
int x = 10;
free(&x);

/* C：free 之后再用 */
int *p = malloc(sizeof(int));
*p = 5;
free(p);
printf("%d\n", *p);

/* D：数组越界写堆 */
int *a = malloc(5 * sizeof(int));
a[5] = 1;

/* E：malloc 大小算错 */
int *a = malloc(5);          /* 想开 5 个 int */
a[4] = 1;
```

**必须回答**：
1. A 和 B 通常**立刻崩溃**（堆管理器检测到非法指针），C 和 D 可能**静默破坏数据**
2. E：`malloc(5)` 只给了 5 **字节**，`a[4]` 要访问第 17–20 字节 → 越界。正确写法 `malloc(5 * sizeof(int))`
3. 为什么 D、E 这类"越界写堆"最难查？（可能覆盖了堆的管理信息，崩在**很远的地方**）

**记住**：`malloc` 的参数永远是**字节数**，不是元素个数。

## 易错点速查

| # | 错误 | 后果 | 正确 |
|---|---|---|---|
| 1 | 不检查 `fopen` 返回值 | 空指针崩溃 | `if (!fp) ...` |
| 2 | 忘记 `fclose` | 数据丢失、句柄泄漏 | 配对使用 |
| 3 | `"w"` 打开已有文件 | **内容清空** | 确认后再用，或改 `"a"` |
| 4 | `while (!feof(fp))` | 最后一行重复 | 用返回值判断 |
| 5 | `fscanf` 返回值不检查 | 读到垃圾 | 检查个数 |
| 6 | `malloc` 参数写成元素个数 | 越界 | `n * sizeof(T)` |
| 7 | `a = realloc(a, ...)` | 失败时泄漏 | 用临时变量 |
| 8 | `free` 后继续用 | 未定义行为 | 置 `NULL` |
| 9 | 重复 `free` | 崩溃 | 只释放一次 |
| 10 | 释放二维数组顺序错 | 泄漏 | 先行后主 |
| 11 | 文本模式读写二进制 | 数据被 `\r\n` 破坏 | `"rb"` / `"wb"` |
| 12 | `ftell` 后忘 `rewind` | 读不到内容 | 回到开头 |

## 参考答案（仅分析题）

**第 12 题**：`feof` 在**读操作失败之后**才置位。所以 `while (!feof(fp))` 会先判断（此时还没失败），进循环，`fgets` 失败但 `buf` 保留旧内容，于是多打印一次。

**第 20 题**
- A：重复 `free` → **立即崩溃**（堆管理器发现指针不在空闲链表里）
- B：`free` 非堆地址 → **立即崩溃**
- C：use-after-free → **可能读到旧值，也可能崩溃**（最阴险）
- D：越界写堆 → **可能静默破坏堆结构，崩在别处**
- E：`malloc(5)` 只给 5 字节 → 越界写，同上

**第 16 题**：栈通常 1–8MB，100 万个 `int` = 4MB，可能爆栈。堆可以到几 GB。
