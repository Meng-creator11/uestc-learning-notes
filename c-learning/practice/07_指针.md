## 开始前：知识点自查

- [ ] `&x` 取地址，`*p` 解引用（取出 `p` 指向的值），两者是逆运算
- [ ] `int *p` 里的 `*` 是**类型的一部分**，不是解引用
- [ ] 指针存的是地址，地址是整数，但指针**不是**整数（类型决定"跳几格"）
- [ ] `int *p` 加 1，地址加 **4**（不是 1）
- [ ] `a[i]` 完全等价于 `*(a + i)`
- [ ] 数组名 `a` 在大多数场合等价于 `&a[0]`，但**它不是指针变量**（不能 `a++`）
- [ ] 指针未初始化就是"野指针"，解引用它会崩
- [ ] `NULL` 是"不指向任何地方"，解引用前必须检查

## 内存图：先把这张图看懂

```c
int x = 42;
int *p = &x;
```

```
变量名      地址          内存
  x       0x7ffc1000    ┌──────┐
                        │  42  │
                        └──────┘
                             ▲
                             │ 存的地址是 0x7ffc1000
  p       0x7ffc1008    ┌──────┐
                        │ 0x...1000 │
                        └──────┘
```

- `x` 的值是 `42`
- `&x` 是 `0x7ffc1000`
- `p` 的值是 `0x7ffc1000`
- `*p` 是 `42`（顺着地址找过去）
- `&p` 是 `0x7ffc1008`（指针自己也有地址）

**记住一句话**：`p` 是"一张写着地址的纸条"，`*p` 是"照着纸条找过去，看那里有什么"。

### 10. 指针数组 vs 数组指针 ★★★

**要求**：下面两个声明的区别是什么？各写一段代码用起来。

```c
int *a[5];      /* ① */
int (*b)[5];    /* ② */
```

**提示**：
- ① 是"数组，元素是 `int*`"——5 个指针
- ② 是"指针，指向含 5 个 int 的数组"

**判断技巧**：看 `[]` 和 `*` 谁先结合。`[]` 优先级高于 `*`，所以 ① 先结合 `[5]` 成为数组。

**必须做到**：
1. 用 `sizeof` 验证：`sizeof(a)` 是 40（5 个指针 × 8），`sizeof(b)` 是 8（一个指针）
2. 用 `b = &arr;`（`arr` 是 `int[5]`），然后 `(*b)[i]` 访问元素

**这题考试常考，用 `sizeof` 验证是最快的确认方式。**

### 13. 指针版字符串函数 ★★

### 20. 指针 bug 排查 ★★★

**要求**：下面五段代码都有 bug。逐个指出，并说明"会导致崩溃 / 静默错误 / 内存泄漏"中的哪一种。

```c
/* A */
int *p;
*p = 10;

/* B */
int *p = malloc(10 * sizeof(int));
p = NULL;

/* C */
int a[5];

p += 10;
*p = 1;

/* D */

## C 组 · 链表（21–28）

> **链表的核心思想**：数组要求元素挨在一起，链表只要求"每个元素知道下一个在哪"。
>
> ```c
> struct Node {
>     int data;
>     struct Node *next;
> };
> ```
>
> 只要画得出"箭头怎么接"，链表就不难。**每次改 `next` 之前，先在纸上画。**

```

**要求**：
1. 考虑删除头节点
2. 考虑连续多个相同值
3. 记得 `free` 掉被删的节点

**必须回答**：
1. 删除时为什么要保存 `prev`（前驱）？
2. 头节点被删时，`prev` 是 `NULL`，代码怎么处理？（单独判断，或者用一个"哑节点 dummy"简化）
3. **不 `free` 会怎样？**（节点从链上摘下来了，但内存还在 → 泄漏）

**哑节点技巧**：`struct Node dummy; dummy.next = head;` 然后从 `&dummy` 开始处理，最后 `head = dummy.next;`——这样头节点就不用特判了。用一次你就爱上它。

### 25. 链表反转 ★★★

**要求**：原地反转单链表。

**样例输入/输出**
```
1 -> 2 -> 3 -> 4 -> 5
-> 5 -> 4 -> 3 -> 2 -> 1
```

**要求**：用三个指针 `prev`、`cur`、`next`，**不许新建节点**。

**提示**：
```c
while (cur != NULL) {
    next = cur->next;    /* 先保存 */
    cur->next = prev;    /* 反转 */
    prev = cur;          /* 前进 */
    cur = next;
}
```

**必须回答**：为什么**必须**先保存 `next`？如果先写 `cur->next = prev;` 会丢什么？

**这题是链表题里的"Hello World"**，笔试出现率极高，必须能**不看提示**写出来。

## 易错点速查

| # | 错误 | 后果 | 正确 |
|---|---|---|---|
| 1 | `int *p; *p = 1;` | 野指针，崩溃或静默改坏 | 先指向有效内存 |
| 2 | `*p++` 理解错 | 取到下一个元素 | 后置 `++` 是"用完再加" |
| 3 | `a++`（`a` 是数组） | 编译错误 | 数组名不是变量 |
| 4 | 返回局部数组地址 | 悬空指针 | `static` 或 `malloc` |
| 5 | `free` 后再用 | use-after-free | `free` 后置 `NULL` |
| 6 | `free` 两次 | 崩溃 | 只 `free` 一次 |
| 7 | 忘记 `free` | 内存泄漏 | 每个 `malloc` 配一个 `free` |
| 8 | 指针相减忘了同数组 | 未定义行为 | 只对同一数组做 |
| 9 | `int *a[5]` 当成数组指针 | 类型全错 | `int (*a)[5]` |
| 10 | 链表改 `next` 顺序反了 | 断链/死循环 | 先连新节点，再断旧连接 |
| 11 | 忘记更新 `head` | 头部操作丢失 | 函数返回新 `head` |
| 12 | `malloc` 不检查 `NULL` | 极端情况下崩 | `if (!p) ...` |

## 参考答案（仅分析题）

**第 6 题**：`q - p = 5`。指针相减返回的是**元素个数**，不是字节数。编译器自动除以 `sizeof(int)`。

**第 12 题**：`sizeof(a)` 在函数内是 8（指针大小），不是 40。数组作参数时退化成 `int *`。

**第 20 题**
- A：野指针，**可能崩溃也可能静默改坏别的变量**（最危险）
- B：`p` 被覆盖成 `NULL`，`malloc` 的那块内存再也无法释放 → **内存泄漏**
- C：越界写，**可能崩溃也可能静默改坏**（`a` 之后的内存）
- D：字符串字面量在只读段，写它 → **通常崩溃**（段错误）
- E：use-after-free，**可能崩溃，也可能读到旧值**（最阴险的一类 bug）
